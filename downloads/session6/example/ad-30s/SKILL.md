# ad-30s

한 줄 주제를 받아 **대본·샷 목록 → 인물·제품·장소 시트와 단독 컷 → H3 클립 → Remotion 편집 → earshot 소리·최종 출력** 순서로 진행한다. 주제에 필요한 인물, 제품, 소품, 장소만 구성한다. 특정 작품의 등장 대상·색상·장소·음악·무대사를 공통 조건으로 가져오지 않는다.

## 작업 범위와 기본값

- 이 스킬이 들어 있는 `.agents/skills/ad-30s/`에서 세 단계 위를 프로젝트 루트로 확인하고, 제작 작업 루트는 그 아래 `session6/`로 고정한다. 현재 셸 위치만으로 루트를 추측하지 않는다.
- **제작 중 새로 만들거나 수정하는 프로젝트 파일은 모두 `session6/` 안에 둔다.** 소스, 다운로드, 프롬프트, 워크플로, 로그, 검수 이미지, 임시파일, 가상환경, 패키지·모델 캐시도 포함한다. 각 도구의 작업 디렉터리와 출력 경로를 명시한다. 사용자 제공 외부 자료와 기존 스킬은 읽기만 하고 필요한 입력은 `session6/inputs/`로 복사한다. 기존 자료와 스킬을 고치거나 전역 설치·설정을 변경하지 않는다.
- 하위 스킬의 예제 경로도 이 범위에 맞춘다. 특히 earshot의 `session5/earshot.ps1`, 가상환경·캐시 경로를 그대로 실행하지 않는다. 지원되는 도구 옵션과 프로세스 범위 환경변수로 캐시·임시 경로를 `session6/`로 지정하고, 경로를 통제할 수 없으면 제약을 알리고 해당 실행을 보류한다.
- 한 줄 주제만 있으면 대상 고객·분위기·메시지를 합리적으로 정해 `session6/brief.md`에 가정으로 기록하고 진행한다. 실제 제품의 미제공 성능·인증·가격·인물 발언을 만들어 광고 문구로 쓰지 않는다.
- 기본 생성안은 **10초 클립 3개, 클립당 5초 샷 2개**, 처음부터 **세로 9:16, 공급자의 480p 옵션**이다. 샷 구성은 주제에 맞게 조정할 수 있지만 최종은 **30.000초, 24fps, 720프레임**으로 맞춘다. 생성 결과의 컷 수·길이가 계획과 같다고 가정하지 않는다.
- 최종 납품은 `session6/final/ad-30s.mp4`, **1080×1920, 9:16, H.264/AAC, 소리 포함**이다. 480p 소스의 로컬 확대는 세부 묘사를 복원하지 않는다. 클라우드 업스케일·고해상도 재생성은 기본 실행에 포함하지 않는다.
- 기존 `session6/`가 있으면 상태와 실제 파일을 확인해 이어서 작업한다. 원본을 보존하고 재생성 후보는 버전별로 저장한다. 계획·검수 문서의 파일 경로는 프로젝트 루트 기준이며, Remotion 코드의 `staticFile()` 경로는 해당 프로젝트 `public/` 기준이다.

## 기존 스킬을 읽고 호출할 위치

이 문서는 제작 순서와 승인 조건을 정한다. 도구별 실행법은 아래 원래 스킬에서 해당 단계 직전에 읽는다. 이 작업의 `session6/` 범위, 생성 승인, 종료 시 서버 정리는 하위 스킬의 예제·기본 동작보다 우선한다.

| 시점 | 읽을 원래 스킬 | 맡기는 작업 |
| --- | --- | --- |
| 3단계 H3 준비·제출 직전 | [comfy-cli](../comfy-cli/SKILL.md) | CLI·실제 스키마·공식 템플릿 확인, 워크플로 구성·검증, 견적, 승인 후 업로드·제출·추적·다운로드 |
| 4단계 프로젝트 생성·편집, 5단계 믹스·렌더 직전 | [remotion-best-practices](../remotion-best-practices/SKILL.md) | 라우터를 읽고 create·markup·multimedia·audio·render 중 필요한 참조만 따라간다. Studio는 작업 중 검수에 사용하고 종료 시 끈다. |
| 5단계 소리 후보를 판단하기 전과 최종 소리 검수 때 | [earshot](../earshot/SKILL.md) | 로컬 CPU로 후보 선택·구간 추출·음량·영상 동기 분석. 수치를 근거로 판단한다. |

필수 스킬이 없거나 도구가 동작하지 않으면 정확한 누락을 알리고 그 도구가 필요한 단계만 보류한다. 준비된 문서 작업은 계속할 수 있다. 없는 스킬을 읽었다거나 도구를 실행했다고 쓰지 않는다.

## 1. 대본·샷 목록

**입력:** 한 줄 주제, 선택적으로 제공된 제품·인물·브랜드 자료.

**출력:** `session6/brief.md`, `session6/script.md`, `session6/rules.md`, `session6/shots.json`.

1. 30초 동안 전달할 메시지 하나와 시작·전개·마무리를 정한다. 음악·환경음·대사·자막·CTA의 사용 여부는 이번 주제에 맞춰 명시한다. 텍스트·엔딩 화면을 쓴다면 기존 30초 안에 시간을 배정한다.
2. 샷마다 ID, 소속 클립, 전체·클립 내부 시작/끝 시각, 길이, 세로 구도, 보이는 대상, 행동, 카메라, 소품 위치·움직임, 소리, 참조 자산 ID·예정 경로를 기록한다.
3. `rules.md`에는 바뀌면 안 되는 얼굴·복장·제품 형상·색·수량, 소품 소유·연결부, 시선·동선·화면 좌우, 장소 구조·광원·시간대를 기록한다. 같은 장소의 연속 샷은 같은 확정 장소 단독 컷을 재사용한다.
4. `shots.json`에 계획 상태와 실제 파일의 준비 상태를 구분한다. 제작 예정 경로와 존재하는 파일을 혼동하지 않는다.

**확인:** 전체 구간에 빈틈·중복 없이 30초가 되는지 계산한다. 각 샷의 핵심이 세로 화면에서 읽히는지, 행동·제품 상태·손·시선이 이어지는지 대본과 JSON을 대조한다.

**하지 말 것:** 이 단계에서 영상 생성, 특정 예시의 출연 구성·무음 규칙 고정, 화면에 없는 발언·근거 없는 효능 추가, 제목·전환을 30초 밖에 덧붙이기.

## 2. 시트와 영상 참조용 단독 컷

**입력:** `session6/script.md`, `rules.md`, `shots.json`, `inputs/`의 제공 자료.

**출력:** `session6/sheets/<asset-id>.png`, `session6/views/<asset-id>.png`, `session6/asset-manifest.json`, `session6/review/references.md`. 이미지 생성·크롭 지시는 `session6/prompts/images/`에 보관한다.

1. 필요한 자산을 인물·제품/소품·장소로 나누고 Codex 내장 이미지 생성 도구로 시트를 만든다. 유료 Comfy 이미지 생성이나 별도 유료 API로 임의 전환하지 않는다. 제공된 실제 제품 이미지를 가능한 한 외형 기준으로 쓴다.
2. 인물은 같은 대상의 정면·3/4·측면과 얼굴 근접, 제품/소품은 전체·주요 면·연결부·재질, 장소는 같은 공간의 기준 시점과 보조 시점을 정리한다. 중립 배경의 인물·제품 시트에는 불필요한 다른 대상과 글자를 넣지 않는다. 장소 시트는 공간·빛을 확인할 수 있게 만든다.
3. 확정된 시트에서 필요한 칸을 **코드로 원본 픽셀 크롭**하여 단독 컷을 만든다. 경계·여백을 확인한 좌표와 원본을 manifest에 남긴다. 크롭만 할 때 재생성하지 않는다.
4. 얼굴·제품 핵심이 너무 작거나 흐리면 품질 보류로 표시한다. 필요하면 얼굴/디테일을 기준으로 해당 단독 컷만 보완하고 이전 컷은 보존한다. 전체 시트를 무조건 다시 만들지 않는다.
5. manifest에 자산 ID, 실제 시트·단독 컷 경로, 크기, 생성/크롭 방법, 원본·보완 버전, 검수 결과와 사용할 샷을 연결한다. 경로와 준비 상태를 `shots.json`에도 반영한다.

**확인:** 시트와 단독 컷을 실제로 열어 외형·색·제품 수량·구조·빛 방향을 비교한다. 단독 컷에 다른 칸·글자·불필요한 대상·잘린 핵심이 없는지 확인하고 치수를 기록한다. 영상 제출 전에 품질 보류가 해결됐는지 확인한다.

**하지 말 것:** 다중 뷰 시트를 그대로 영상 참조로 넣기, 시트의 배치·중립 배경을 본편 배경으로 복제하기, 좌우 반전으로 연결 규칙 바꾸기, 검수 실패한 컷으로 유료 영상 제출하기.

## 3. H3 프롬프트·견적·승인·클립

**입력:** 준비 완료된 `session6/shots.json`, `rules.md`, `asset-manifest.json`, `views/`의 단독 컷.

**출력:** `session6/prompts/clip1.txt` 등, `session6/prompts/references.json`, `session6/cloud/`의 템플릿·편집 원본·API 워크플로, `session6/cloud/estimate.md`, `approval.md`, `jobs.json`, `session6/clips/clip1.mp4` 등, `session6/review/clips/`.

### 프롬프트와 제출 전 검증

1. `comfy-cli`를 읽고 설치 버전·도움말·H3 모델 정보·템플릿과 실제 노드 스키마를 조회한다. 출발점은 `api_minimax_h3_r2v`와 `MinimaxHailuo03ReferenceNode`지만 이름·슬롯·enum은 현재 제공값으로 확인한다. 요청 모델은 **MiniMax H3**이며 H3 Max·다른 모델로 임의 교체하지 않는다.
2. 실제 스키마가 **480p와 9:16, 필요한 길이·참조 수**를 지원하는지 확인한다. 지원하지 않으면 그 사실과 선택지를 알리고 해당 영상 생성을 보류한다. 예전 자료의 768P·16:9로 대체하지 않는다.
3. 영어 R2V 프롬프트는 `subject_definitions`, `summary`, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music` 순서로 쓴다. `<Subject n>`과 `<Picture n>`의 대응과 유지할 속성을 정의한다. 각 클립의 시간은 0부터 다시 시작하고 첫 샷은 `[Shot 1]`, 기본 두 번째 샷은 `[Shot 2] At 00:05.000,`으로 쓴다. 샷 길이가 달라지면 실제 계획 시각으로 바꾼다.
4. 기본 참조 묶음은 주체·제품/소품·장소 단독 컷이다. 주제와 스키마에 필요한 장수만 사용하고, 인물이 없는 주제에 인물을 강제하지 않는다. `references.json`에 각 클립의 참조 **배열 순서, 역할, 실제 경로, 길이, 샷 시작 시각**을 저장한다. 참조는 외형·공간·빛의 기준이며 첫 프레임을 그대로 복제하라는 지시가 아니다.
5. 화면에 보이는 요소와 행동·정지 구간·연결 방향을 구체적으로 쓴다. 화면 밖 대상을 배제하려고 그 외형·이름을 부정문에 반복하지 않는다. 좁은 구도, 프레임 경계와 보이는 부분으로 표현하고 제외 조건은 계획 문서에서 관리한다.
6. 템플릿 → 지원되는 recipe/구조 편집 또는 decompose·blueprint → API 산출 순서로 구성한다. 세부 방법은 `comfy-cli`를 따른다. 받은 템플릿·컴파일 산출물의 노드 숫자를 찾아 원시 JSON을 임의 수정하지 않는다. 프롬프트·참조 순서·`SaveVideo`의 MP4/H.264 설정을 대조한다.
7. 스키마 검증과 `comfy run --workflow <파일> --where cloud --print-prompt`까지만 실행한다. 이 미리보기는 생성도, 실제 품질 확인도, 숫자 비용 견적도 아니다. 로컬 참조 경로는 업로드 전 placeholder라고 표시한다.

### 크레딧 승인 경계

- **유료 영상 생성 전에 반드시 견적을 사용자에게 보여 주고 명시적 승인을 기다린다.** 한 줄 주제, 제작 요청, 이전 회차의 승인을 이번 견적의 승인으로 취급하지 않는다.
- 실행 시점의 [Comfy 공식 파트너 가격표](https://docs.comfy.org/tutorials/partner-nodes/pricing)에서 해당 H3 모드·480p·길이의 단가를 확인하고 확인일·출처를 `estimate.md`에 남긴다. 예전 회차의 단가·총액을 재사용하지 않는다. 초당 요금이면 `단가 × 클립 초 × 제출 수`로 계산하고, 현재 요금 단위가 다르면 그 단위에 맞춰 계산한다.
- 모델·모드·해상도·비율·각 클립 길이·제출 수·클립별 예상 크레딧·총 예상 크레딧을 표로 보여 준다. 가격표 계산값인지 CLI 견적인지, 변동·재생성 비용은 별도인지 구분한다. 단가를 확인하지 못하면 숫자를 지어내지 말고 유료 제출을 보류한다.
- 승인 전에는 로그인·인증 변경·참조 업로드·`assets push`·제출·`--allow-spend`를 실행하지 않는다. 기존 인증으로 가능한 무료 조회·로컬 준비와 검수만 계속한다. 인증이 필요한 조회는 필요성을 알리고 보류한다.
- 승인 응답을 받은 뒤 `approval.md`에 승인된 견적 버전, 클립·설정·제출 횟수, 사용자 승인 내용을 기록한다. 설정·대상·횟수 또는 비용이 승인 범위를 벗어나면 변경 견적과 새 승인을 받는다. 재생성·유료 업스케일도 별도 견적과 승인 대상이다.

### 승인 후 실행과 확인

1. 필요한 단독 컷만 Comfy CLI로 업로드한다. 응답의 실제 `cloud_name`을 지원되는 원본 편집 경로로 LoadImage에 연결하고 다시 구성·미리보기·검증한다. 로컬 파일명이나 예전 Cloud 이름을 그대로 제출하지 않는다. 재로그인이 필요하면 사용자에게 알리고 인증 완료 전에는 제출하지 않는다.
2. 승인 범위에 한해서 `--allow-spend`로 제출하고 반환 job/prompt ID와 설정·상태를 `jobs.json`에 즉시 기록한다. 첫 클립을 내려받아 검수한 뒤 다음 승인된 클립을 진행한다. 추적·대기·다운로드 명령은 실제 CLI 도움말을 따른다. 출력 위치는 `session6/` 안으로 명시한다.
3. 실패·시간 초과 시 원문 오류와 ID를 남기고 **자동 재제출하지 않는다**. 제출 결과가 불명확하면 기존 ID의 상태부터 확인한다. 오류 1026을 포함해 재시도는 새 비용·승인 범위를 확인한 뒤 진행한다.
4. 가능한 경우 제출 전후 크레딧을 기록한다. 계정 잔액 차이와 해당 작업에 확정된 과금은 구분하고, 확인할 수 없는 실제 비용은 미확인으로 표시한다.

**확인:** ffprobe로 실제 길이·크기·SAR/DAR·fps·프레임 수·오디오 트랙을 재고 기록한다. 480p는 공급자 옵션 이름으로 남기며 실제 픽셀 치수를 추정하지 않는다. 처음·중간·끝과 컷 주변 프레임을 추출해 열고 외형·제품·세로 구도·빛·동작을 확인한다. 소리를 평가해야 하면 그 시점에도 `earshot`을 먼저 사용한다.

**하지 말 것:** 승인 전 영상 실행, 동의 오류를 없애려고 `--allow-spend` 추가, 일괄 무한 재시도, 자동 고해상도 생성·업스케일, 프롬프트의 5초 컷·10초 길이를 실제 결과로 간주하기.

## 4. 실제 컷을 기준으로 Remotion 편집

**입력:** `session6/clips/`의 실제 영상, `shots.json`, `script.md`, `rules.md`.

**출력:** `session6/clips.json`, `session6/edit/shots.md`, `session6/edit/edit.json`, `session6/edit/frames/`, `session6/remotion/` 프로젝트, `session6/remotion/src/shots.json`, `session6/remotion/public/media/`, `session6/edit/review/`.

1. `remotion-best-practices`와 필요한 참조를 읽는다. ffmpeg·ffprobe·Node 및 Remotion 실행 가능 여부를 확인한다. 의존성 설치가 필요하면 `session6/` 내부 프로젝트·환경과 캐시만 사용한다.
2. `clips.json`에 선택 소스의 실제 경로·측정값·SHA-256을 기록한다. 후보가 여러 개면 대표·연속 프레임을 직접 비교해 이유를 기록한다. ffmpeg scene 검출은 컷 후보로만 사용하고 앞뒤 프레임으로 확정한다. 계획과 다르면 **실제 영상이 편집 기준**이다.
3. 실제 각 샷의 처음·가운데·끝을 저장하고 열어 `edit/shots.md`에 원본 IN/OUT·길이·화면 내용·문제·채택 이유를 적는다. 계획보다 샷이 많거나 컷 시각이 어긋난 사실을 숨기지 않는다.
4. 원본 fps가 다르면 원본을 보존한 채 로컬 파생 소스를 24fps로 규격화하고 이후 인덱스의 기준 소스를 명시한다. `edit/edit.json`을 **순서·IN/OUT·전환·길이의 단일 기준**으로 삼고 Remotion이 읽게 한다. 소스 ID·경로·해시, 0부터 세는 `[IN, OUT)` 프레임, 전환 중첩을 저장한다. 길이는 `사용 프레임 합 − 중첩 프레임 합 = 720`으로 검증한다.
5. 기본은 하드컷이다. 시간 경과에 필요하고 사용 가능한 핸들이 있을 때만 디졸브를 쓴다. 0.25초라면 24fps에서 6프레임을 중첩 계산에 포함한다. 부족한 길이는 다른 사용 가능 구간이나 계획된 광고 화면으로 해결하고, 해결할 수 없으면 부족량을 보고한다. 추가 유료 생성에는 3단계 승인이 필요하다.
6. `session6/remotion/`에 프로젝트를 만들고 `public/media/`에 영상과 분리 가능한 원본 소리를 준비한다. 한 프레임 렌더로 구성·경로를 먼저 확인한다. Studio의 실제 URL에서 미리보기를 확인하고 시작한 PID·포트·명령을 `session6/review/servers.json`에 기록한다.
7. `src/shots.json`은 **샷별 핵심 하나, 화면 내 위치·확대·필요한 이동**을 정하는 구도 파일로 쓴다. 시간·순서는 `edit.json`을 따른다. 처음부터 세로인 소스는 구도를 먼저 살리고 필요한 경우만 보정한다. 가로 제품이 창보다 넓으면 가까이 잡아 천천히 훑는 방법을 고려한다.
8. 본편 프레임만으로 메시지가 부족할 때만 보강 이미지 계획을 세우고 `public/assets/`와 그 안의 `asset-manifest.json`에 사용 위치·제작 방법을 기록한다. 확정된 제품/본편 프레임을 참조하고 글자는 Remotion에서 얹는다. 장면 순서를 바꾸면 타임라인·자막·이후 사운드 큐도 함께 다시 계산한다.

**확인:** 샷별 세로 대표 프레임 격자, 움직이는 핵심의 시작·끝, 모든 컷 앞뒤와 2초 간격 격자를 저장해 실제로 연다. 잘린 얼굴·제품·손, 검은 프레임, 의도하지 않은 반복·정지, 뒤집힌 동선, 글자 겹침을 확인한다. 구도 수정은 `src/shots.json`, 순서·길이 수정은 `edit.json`에 반영한다.

**하지 말 것:** 원본 덮어쓰기, 실제 컷을 무시하고 5초마다 자르기, 30초를 채우기 위한 임의 루프·정지·배속, 모든 주제에 같은 디졸브 강제, 색 띠·복제·흐린 배경으로 세로 여백 채우기, 다른 회차의 편집 프로젝트를 수정하기.

## 5. earshot으로 소리 선택·배치·최종 출력

**입력:** 확정된 `session6/edit/edit.json`, `session6/remotion/src/shots.json`, 영상·원본 소리, `brief.md`의 소리 방침.

**출력:** `session6/sound-review/`의 분석·출처 검증 기록, `session6/remotion/public/sound/`의 선택 음원·`credits.md`, `session6/sound-plan.md`, `session6/remotion/src/audio-cues.json`, `session6/final/ad-30s.mp4`, `session6/final/description.txt`, `session6/final/review/`.

1. `earshot`과 Remotion의 audio·render 지침을 읽는다. earshot 실행기·가상환경이 필요하면 `session6/earshot.ps1`, `session6/.venv-earshot/` 등 이 작업 안에 준비한다. CPU만 사용하고 모델·보조 캐시는 `session6/.cache/`로 지정한다. `doctor`로 실제 동작을 확인하고 신규 모델 다운로드가 있으면 크기·시간을 기록한다.
2. 분위기를 한 줄로 정하고 샷별 필요한 소리를 표로 만든다. 음악은 필요할 때 한 곡을 선택하며, 환경음만으로 충분한 주제는 그 선택을 유지한다. 효과음은 보이는 동작이나 대본에서 정한 사건에만 맞춘다.
3. 상업 사용·편집이 허용되는 후보를 출처 페이지와 라이선스 원문으로 확인한다. 제목·작성자·출처 URL·다운로드 URL·라이선스·크레딧 의무·사용 구간·가공 내역을 기록한다. 원본 음원은 `session6/sound-review/sources/`에 보존하고, 전체 크레딧 문구는 `public/sound/credits.md`에 쓴다. 예시 작품의 음원·라이선스를 그대로 가져오지 않는다.
4. 후보를 `rank`/`match`, 구간을 `find`, 실제 사용할 trim을 `describe`·`measure`로 분석한다. 실제 녹음 여부가 중요한 후보에는 `realness`도 사용한다. head/tail cut 후보는 그대로 사용하지 않고 경계를 보정한 뒤 다시 확인한다. 분석 JSON, 구간·게인·페이드, 길이·LUFS·피크·선택 근거를 `sound-review/`와 `sound-plan.md`에 남긴다.
5. `audio-cues.json`에 소스 구간·타임라인 프레임·게인·페이드를 기록하고 Remotion에서 음악·효과음·원본 소리를 합성한다. 필요한 원본 환경음을 낮게 살리고 짧은 경계 크로스페이드로 튐을 줄인다. 음악이 핵심 동작음·대사를 가리지 않게 한다. 추가 화면과 크레딧도 720프레임 안에 배치한다.
6. 필수 화면 크레딧은 마지막 6초의 작은 한 줄을 출발점으로 삼되 라이선스와 가독성을 따른다. 제품·인물을 가리지 않게 배치한다. 전체 표기·원본/라이선스 링크·수정 내역은 `final/description.txt`에 넣고 AI 영상 제작 사실을 표시한다. 설명 파일을 만들었다는 사실을 게시 완료로 쓰지 않는다.
7. 완성 요청의 납품물로 `final/ad-30s.mp4`를 렌더한다. 전체 음량은 약 **−14 LUFS**, 트루피크는 **−1.5 dBTP 이하**를 기본 목표로 하고 최종 AAC 파일을 다시 측정한다. 조용한 연출을 해칠 정도로 일괄 증폭하지 말고 조정 이유를 남긴다.
8. 최종 영상에 `earshot timeline`과 `sheet`를 실행하고 `audio-cues.json`을 현재 도구가 요구하는 `--cues` 스키마로 변환해 전달한다. sheet PNG를 실제로 열고 컷뿐 아니라 동작 프레임에 대한 지연·마스킹·소리 중복을 확인한다. 수정하면 새 최종 파일에서 음량·동기를 재검수한다.

**확인:** ffprobe로 30.000초·1080×1920·9:16·24fps·720프레임·H.264/AAC·오디오 유무를 확인한다. 최종 2초 격자·컷 앞뒤·마지막 6초 크레딧 프레임을 열고 전체 디코딩 오류도 검사한다. earshot의 길이·LUFS·dBTP·큐 offset 등 측정값과 해결하지 못한 문제를 `final/review/`에 기록한다. 원본 SHA-256을 대조한다. 사람의 실제 청취 여부와 도구 분석을 구분해 보고한다.

**하지 말 것:** 출처·상업 사용 조건을 확인하지 못한 음원 사용, 파일명이나 파형만으로 소리를 골랐다고 말하기, earshot 점수를 취향·출처·라이선스의 증명으로 사용하기, 외부 오디오 업로드에 임의 동의하기, 화면과 관계없는 효과음 덧붙이기, 게시·전송을 자동 실행하기.
